# The network port: the dedicated server and its restart records

Part of [Network Port](../NETWORK_PORT.md): the two sections about the game server that hosts online rooms. The protocol, the clients and the rest of the design are in that page.

## The dedicated server (`src/ants_server`, v0.0.83)

Decision (2026-09-30): **no NAT traversal in the game**. The game has no real lobby of its own; an external lobby launches it, and for internet play a server that everybody can reach hosts the matches. `ants_server` is that server: a headless program, one process, many rooms, no threads (one `update(now)` per pass over the sockets and the rooms, like the rest of the network code).

* **Room** (`room.hpp`): a seatless `HostLobby` (room code, `min_players` = `max_players` = the expected players) that becomes a seatless `HostSession` with its own `SimulationEngine`, the **referee** (`judge_hashes`: every client's hash of a turn is compared with the referee's own; a seat that differs is told and dropped as a quitter is, the others go on, and the room fails only when no seat agrees). It is made from outside (`RoomSpec`: map file, fog, players 2 - 4, code, seed, wait / load / keep times) and starts by itself: when the expected seats are taken the lobby sends Start, every client loads the map and reports, and the match begins when all have. A client that cannot load or that leaves cancels the start (back to Waiting; a few tries at most, 2 s apart); a room that nobody completes fails after `wait_ms`. Finished and failed rooms are kept for status calls (`keep_ms`) and written to `<code>.json` in `--results-dir`. The result rows are the results screen's (an alliance is one row). A demo room's `keep_ms` is 30 s.

* **The door** (`room_manager.hpp`): every connection (TCP from a LAN or development client, WebSocket through a TLS proxy for browsers, Electron and the desktop game) arrives without a room; the first message must be a Hello within 10 s and its room code (protocol 6) names the room. A Hello for a room that does not exist or is over (`NoSuchRoom`: a finished or failed room is not "a match that has started"; a public room that is over is made again by a Hello that carries a create block, "Protocol 15" below), for a match that is running (`MatchRunning`), another protocol version, or anything else is answered with a Reject and the connection is closed after a short linger so the answer arrives. Limits: 256 rooms, 128 connections that have not said Hello.

* **The public status, `GET /busy` (on the WebSocket port)**: `WsServerOptions::status_path` and `status_body` (`ws.hpp`; the server sets them when `--ws-port` is on: `WsListener::set_status`) make the handshake parser answer one plain HTTP request before it looks at the path and the origin of the door: a `GET` of exactly the status path (`/busy`: no query, no trailing slash, case as written) with no `Upgrade` header, exactly one `Host`, and no body or transfer coding gets `200 OK`, `Content-Type: application/json`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Connection: close` and the text, and the connection closes (`WsHandshakeResult::Status::Answered`; it never becomes a `WsConnection`, so nothing reaches the game). Any other method is 405, a query or another path is no status request (the door's usual 426 / 404), a missing or doubled `Host` or a body is 400, and a text longer than `kWsMaxStatusBytes` (512) is a 500, never a long answer. The text is `{"matches":N,"players":M}` from `RoomManager::busy()`: `matches` counts the rooms whose match is **loading or running with a person in it** (present or catching up; a room that waits for players is no match: a restart would only drop a lobby; a room that a restart brought back also counts for its first 5 minutes, see "Restart records"), `players` the people, **bots not counted**, in rooms that wait or load and the people who are there in a match (a room that is finished, failed or closed holds nobody who plays). No name, no room code, no address and no secret is in it; it costs one pass over the rooms (at most 256) and takes no parameter. `docker/nginx.conf` forwards `https://<site>/busy` to it as an exact location like `/ws`, but GET only (405 otherwise), 404 for a query, no body and no upgrade passed on, one request a second per address with a burst of 5 (503 beyond it) and five-second timeouts. Nothing waits for it before the site's update (`docs/WORKFLOW.md`, "Deploy"): **an update recreates the server's container and pauses every match**: the server writes a restart record for each and the players come back to the same match when it starts again (see "Restart records"; `docs/WORKFLOW.md`, "Deploy"), and there is no drain mode (a server that stops taking new rooms before a restart is a later step). Tests: `test_ws` W1.24 (the parser: every method, path, query, header and body case; the longest text; a real socket: the answer arrives whole, the socket closes, the door still opens for a game), `test_server` S3.81 (the counts through a room's whole life: waiting, loading, running, with a bot, closed, finished), `tests/scripts/test_ants_server.sh` (the real server's answers: 0 and 0, one match with two people while a match runs, 0 and 0 again; a POST is 405, a query 426) and `tests/scripts/test_nginx_conf.py` (the proxy block).

* The site statistics (`GET /stats`, `POST /stats/local` and the database tables) are described in [SITE_STATS.md](../SITE_STATS.md).

* **The replays of the rooms' matches (`replay_store.hpp`, `control.cpp`; [`REPLAYS.md`](../REPLAYS.md) "On the game server", the options and numbers in [`SERVER_REPLAYS.md`](../SERVER_REPLAYS.md#replays))**: the referee's runner calls the room's recorder after every turn it executes (`LockstepRunner::set_on_executed`: observation only, no hash changes). When the match is over, or the room failed or was closed, a match that ran 600 turns (30 seconds) however it ended is encoded (`replay::Recorder::finish`) and handed to the `ReplayStore`, which keeps it as `ants-<MAP>-<YYYYMMDD>-<HHMMSS>Z[-<n>].antsrep` (the UTC time the match ended) in one folder of the results volume. A seat of a person has the name that the room showed everybody (`Room::replay_begin`; `replay_person_name`: printable ASCII, 32 characters, the blanks at both ends cut), except that the words that the game itself uses for a player without a name ("Player", "Player 1" to "Player 4") and an empty name leave the seat without one, and the readers show its color; a bot's seat has its display name; no address, room code, key or chat is in it, and the names are public wherever the public door is on. The store touches only files of that form, reads the age of a file from its name, finds, reads and deletes a file by a name from its own index (never by a path from outside), and writes it whole or not at all (a temporary name, then a rename, never a replace). A room that was brought back from a restart record does not record. The control interface lists, gives and deletes the files behind the secret; the second door, `--replay-port` (`ctl::HttpServer::listen_public`: no secret, GET only), gives `GET /replays` and `GET /replays/<file>` and nothing else, and `docker/nginx.conf` passes those two addresses to it with limits of its own and a short cache of the list. Tests: `tests/test_server/test_replay_store.cpp` (the store), S3.160 - S3.175 in `tests/test_server/replay_tests.hpp` (whole matches, played again from the file to the same hash, restarts, demo rooms, the routes and the public door, the names that are kept and the ones that are not), CTL2.22 and CTL2.23 (the read-only HTTP door), `tests/scripts/test_nginx_replays.py` (the nginx blocks, read and run).

* **The map store** (`map_store.hpp`): the folder of `.lvl` files from `--maps`; a name is only a name in the folder (the protocol's `valid_map_name`: never a path), a room is refused (404 / 400) when the map is missing or does not load, so a room that exists can always be played. The Docker image carries the six maps of the original game in `/maps`; a folder mounted there replaces them (the lobby keeps the library and syncs it).

* **The control interface** (`control.hpp`, HTTP + JSON, `ants_ctl`): `POST /rooms`, `GET /rooms`, `GET /rooms/<code>`, `DELETE /rooms/<code>`, `GET /stats`, `GET /replays[?limit=N]`, `GET /replays/<file>`, `DELETE /replays/<file>` (the kept replays, below), every call behind the bearer secret (constant-time compare). The secret is never read from the command line (a command line is visible to every user): it is `ANTS_SERVER_SECRET`, or, when that is not set, a random secret (32 bytes of the operating system's generator, 64 hex digits) that the server makes the first time it starts and keeps in a file (`--secret-file`, default `control-secret` in `--results-dir`, an explicit `--secret-file` wins) (`src/ants_server/secret.cpp`). It is shown in the log once, the moment it is made (before the ports are opened), and read from the file at every later start. The file is made all at once: the complete secret goes to a temporary file next to it, which is linked to the final name (POSIX `link()`, Windows `MoveFileEx` without replacing), so servers that start at the same moment share one secret and a crash leaves no half-written file. On POSIX only its owner can read it (mode 600); **on Windows the server sets no permissions and the file takes those of its folder**. A file that already exists is used as it is (its owner and mode are the operator's responsibility, a symbolic link is followed); one that is no usable secret (not a regular file, empty, outside 32 - 256 characters, a space or control character, more than one line, bigger than 1,024 bytes) stops the server and is never overwritten. It listens on the loopback address; a deployment that needs more says so explicitly (`--ctl-any-interface`, for a container whose host maps the port to its own loopback address). The lobby's backend calls it; room codes first, per-player tokens (the Hello carries one already, the game never interprets it) when the lobby wants to check who joins.

* **Clients**: the same game, `--join HOST:PORT --room CODE` (a Hello with the room code; a lobby launches it with the code). `NetGame` recognises a server's room by its **missing Host slot**: no host migration (a client whose server link dies loses the match, it does not elect itself the host of a one-player game; the server drops the seat at the same tick for everybody else), and the match starts when the room says so: when every seat is taken, or, since protocol 7, when the room's **leader** (the first player who joined) presses START (below). Everybody else's screen waits.

* **A room never waits for a seat that lags (protocol 8)**: the room's host has no seat, so it keeps sealing a turn every 50 ms whatever lag a seat has (a room that HOLDS seats, protocol 10, pauses for a seat whose connection is LOST, and for nothing else: "Reconnect", below); a seat that falls behind is announced to the others (`Lag`, "Bob is lagging (12 s behind)") from 3 s, catches up alone at up to 4x ("Catching up..."), and is dropped at 60 s behind or after 30 s without an acknowledgement (the old rule held the room up for 3 s and then for 20 s). `RoomStatus::turns` is one per tick now (turns of 50 ms). See "What the player feels: ... Who waits for whom".

* **Deployment**: `Dockerfile.server` (a slim Debian image, pinned in the file, builds the program alone with `-DANTS_BUILD_APP=OFF`, runs unprivileged, healthcheck = a connection to the game port), `docker-compose.server.yml` (example). The public site opens no TCP port (neither compose file publishes the server's): the WebSocket port goes behind the nginx that ends TLS (the proxy lines are in the header of `ws.hpp`), and the browser page and the desktop game both reach the server through its `/ws`; the server's TCP game port (`--port`) is for a LAN or development server (publish it only there); the control port is for the lobby's backend only. Capacity: a match costs about 83 microseconds of one core per tick on average (map sweep, 586 maps), so a core holds hundreds of games; the memory of a room is the engine (a few MB).

* **The browser as a client (v0.0.84)**: `WasmWsConnection` (`wasm_ws.hpp`, Emscripten only, `-lwebsocket.js`) is a `Connection` over the page's own WebSocket; `NetGame::join_url` / `--join-url ws[s]://...` joins through it, and the guest branch of `begin_match` is compiled in the web build (no peer listener, no links between guests: a server's room has no Host slot, so migration is off). The page reads `?join=/ws&room=&seat=&name=[&embed=1][&aspect=16:9|4:3]` (`web/shell.html`; `join` must be a path on the same site, everything is validated before it becomes an argument). **`name` is the name that was chosen on the page that made the address** (web/lobby.html always puts the parameter in for its own frames, windows and Join button, empty when none was chosen: the game says Player); **an address of a join that has no `name` parameter at all is a link that somebody shared, and the game page asks for the name before the game starts (so before it connects)**: `ANTS_PAGE.asksForName`, never for `embed=1`, a card over the page that shows the name (a login's or a guest's, never typed), a Join button and Enter; the rules of a name are the desktop start menu's (printable ASCII, at most 32 characters, nothing that starts with "Bot ("), and a game that was given a name loses the parameter from the address bar, so that a copy of its address asks too (`web/lobby.html` shows a name only as text and puts it into a link with `encodeURIComponent`; `tests/scripts/web_name_check.js`); nginx passes `/ws` to the server's WebSocket port (`docker/nginx.conf`: the backend name is resolved per request, so the site starts without the server).

* The front page (the lobby at `/`: its routes, rules, client and checks) is described in [PLAY_IN_BROWSER_HOME.md](PLAY_IN_BROWSER_HOME.md#the-game-page-and-its-addresses), and the page's picture, the pointer in fullscreen and the margin of a windowed page in [PLAY_PICTURE.md](../PLAY_PICTURE.md#a-169-picture-that-fills-the-page).

* **Hardening from the security review (v0.0.84)**: the WebSocket output buffer grows with slack (a flood of pings cost quadratic time: 762,000 pings took 8.1 s, now 0.024 s); the control interface gives a new connection the slot of the oldest one that is waiting for its head with nothing unread (the door of the server does the same with connections that have not said Hello), so idle connections cannot lock either out. From the review of the release itself: all millisecond deadlines are wrap-safe (`clock.hpp`: the server's clock is its uptime and wraps after 49.7 days; a signed comparison against a deadline left at 0 stopped rooms from starting after 24.8 days); a seat that holds the match up for 20 s is dropped (`laggard_drop_ms`; protocol 8 replaced it: a server's room never waits, see "Who waits for whom") and a running room has a wall-clock limit (`max_run_seconds`, 2 h; demo rooms 30 min); a room with no keep time is still reported; the browser client says Hello when the socket opens (a hidden tab runs no frames).

* **Bot seats (v0.0.85, `docs/BOTS.md`)**: no wire change (`SlotState::Bot` is part of protocol 6). `HostLobby::add_bot` / `remove_bot` (a slot of state `Bot`: it counts as a player, its round trip is 0 so its thumb is good, the start never waits for it; Fog of War and a bot refuse each other in `set_fog`, `add_bot` and `start`; a person whose name starts with "Bot (" is renamed, so the slot state and the name are the only way to tell a bot), `HostSession::add_bot_seat` / `submit_bot` (the host acknowledges every turn for the bot seat, otherwise the sequencer would stall after `max_lag_turns` = 60 turns (3 s; 30 turns before protocol 8); the issuer is stamped by the sequencer; a bot seat never reports a hash and is never dropped for silence), `NetGame::add_bot` / `remove_bot` / `submit_bot`. The bot runs on the host's machine only; when the host leaves its bot seat leaves with it: the new host drops every seat of the roster that did not follow (the bot has no endpoint), the survivors stay identical (suite 2.20, AI5.5).

* **Not built yet**: a token check by the lobby (the bots of a server's room are built since protocol 11: see "Protocol 11"). Built since: the recording of every match as a replay file, the tool that plays it and the server's keeping of the matches of its rooms ([`REPLAYS.md`](../REPLAYS.md)), the in-game host / join screens for `--join --room` (v0.0.97, "Joining and hosting from the desktop start menu", below) and the game's own clients for the way back after a lost connection (release B, "Reconnect", below).

## Restart records: a running match survives a restart of the server

A request: that the server must not keep rebooting and kicking the people who play online out of the game, and so a running match has to survive a restart of the server. Before this section every redeploy (it recreates the server's container) and every crash ended every running match: the server held each match only in memory. Now a room that holds seats (protocol 10, "Reconnect") keeps a **restart record** on the results volume from the moment its match is fixed until the room is over, and a server that starts again brings the matches back, with every seat held, so that the players come back with their keys. **No message and no protocol number changed** (the version stays 12): the way back is the one of "Reconnect"; what is new is that the server survives it.

**What a player sees.** The server's rooms keep records (every room holds seats unless the server is started with `--no-reconnect` or the room says `"reconnect": false`), and after a restart each of them is back with its code, paused, every seat held, the others able to vote after 90 s and the cap of the pauses (30 minutes by default) in force. The game's `NetGame` finds the room again by itself (it tries every two seconds, `test_rejoin` RJ1.2) and is given the match: a restart is some seconds of "Connection lost. Reconnecting...", then the catch-up screen, then the match goes on where it was ("What the clients do in release B"). With `--no-reconnect` nothing is kept (a room that holds no seats cannot hold them across a restart).

### The record (`restart_record.hpp`, `restart_record.cpp`)

One file per room in `<results-dir>/restart/` (or `--restart-dir`): `room-<code>-<8 hex digits of FNV-1a of the code>.restart` (the digits keep two codes that differ in case apart on a file system that ignores case; the prefix keeps a room named like a Windows device from naming one). Little endian throughout.

| | |
|---|---|
| file | the magic `ANTSRST1` (the digit is the format: a file of another format is refused as such), then frames |
| frame | `u8 type, u32 length (at most 1 MiB), payload, u32 CRC-32` of the type, the length and the payload |
| HEAD (1) | the first frame, once: the identity of the build that wrote it (game version, protocol, build id: **only the protocol decides**, the others are for the log), the room's specification (code, map and the map file's hash, players, fog, early start, the times, the reconnect settings, the limit of the turn log), the bots (the specification's and the leader's fill, which are told apart), the **start message** of the match (`net::StartMsg` in its wire form, so that the protocol's strict decoder reads it back: seed, roster, names, fog; **the clients' addresses are cleared**: a record has no business keeping them) and the **keys** of the four seats |
| TURNS (2) | `u32 first_turn, u16 count (1 - 4096)`, then `count` turns, each packed as the server's turn log packs it (`u16 command count`, the commands in their wire form): numbered from 0 without a hole; the server writes one turn to a frame |
| CHECK (3) | `u32 turn, u64 hash`: the referee's state hash (`StateHash::total`) after turn `turn`, written when the referee's own runner has run it: every 20th turn (the runner already takes it for the clients' comparison) |

The keys are secrets (a key is all that a seat's owner needs to take it back): the file is for its owner only (POSIX: mode 600 in a folder of mode 700; on Windows it takes the permissions of its folder, like the control secret's file), and a key is in **no log line, status, JSON or result file** (the test collects every text that the server makes through a restart and looks for the keys' hex: S3.91, and the real program's log in S3.95 / S3.96). Nothing of the engine's state is stored: the engine is rebuilt from the start message and the turns, which are the match.

### Writing: what is written when, and why

* **When.** A record is made when the room's start is accepted (the start message and the keys are known: `Loading`, so the seconds of the map's loading and of the wait before the first turn are covered), **before the Start message is sent to anybody** (`HostLobby::set_before_start`: no machine can act on a Start whose match has no record; S3.108), is written for as long as the match runs and is **deleted** when the room finishes or fails (the operator's `DELETE /rooms/<code>` included) or when the start is cancelled (a machine that could not load the map). A waiting room has none. A room that holds no seats, or a server that keeps no records, has none either and its status says why.

* **The head is made all at once**: written to a temporary file next to the record (made new, mode 600), fsync'ed, given its name by a `rename` that replaces what was there, and the folder fsync'ed (best effort: some file systems refuse a sync of a folder, and the rename is then as durable as that file system makes it): a crash leaves no record or a whole head, never half of one (test S3.82 kills a process at its first write).

* **Every sealed turn is `write()`n to the record before it is sent to anybody** (`HostSession::set_on_seal`: after the turn is in the turn log, before the broadcast and before the referee's own runner has it). One `write()` call per turn, nothing buffered. **Why this order:** the operating system keeps what a process has written even if the process dies at that instant (a crash, `kill -9`, the container's death; the volume is a directory of the host), so *the record always holds every turn that any player has run*, and a restart **loses no turn that a player has seen** (S3.88 checks it at every 10 ms step of 30 s of play; S3.96 kills the real program in the middle of a match: the record held 154 turns and the machines had been sent 154; S3.95's SIGTERM runs found 154 or 155 in the record against 154 sent: the record may hold one turn more than any machine has seen, never fewer). A turn that was sealed and not yet written was never sent, so the restarted server seals it again, perhaps with other commands, and nobody has run the old one.

* **The flush: `fsync` once a second per room** (the rooms' flushes are spread over the second by a hash of the code), and for all the records when the server is told to stop. **Why not one per turn:** a turn is 50 ms, a disk's flush takes milliseconds, and the server has one thread that every room waits for. **What the flush is for:** the death of the *machine* (a power cut, a kernel panic): data that the process wrote may be in the page cache only. After that death **up to the last second of turns (20) can be missing from the end of the record**, up to ten seconds (200) on a slow disk (the flush is timed, below); a player whose machine is *ahead* of the record (it ran turns that the disk lost) is told `BadRequest` (more turns than were ever sealed) and must start the match from nothing again, which it can: its key is good (S3.87 tests this; the clients of part B do it). **The flush is timed** (`Room::sync_record`, the review's L6): a flush that takes more than `RestartConfig::slow_sync_ms` (20 ms of real time, `clock_ms`) doubles that room's interval to its next one, to `max_sync_every_ms` (10 s) at the most, and a quicker one brings it back to `sync_every_ms` (a second), so that a slow or busy disk is asked less often by the rooms that find it slow, and the whole loop waits less; the status says the interval (`record_sync_ms`; S3.123).

* **A torn tail.** A write that the machine's death interrupted leaves a last frame that does not fit, has a wrong checksum, or is a zero fill (the file grew, its data did not reach the disk): the reader drops it, the record is the frames before it, and when the room goes on writing the file is cut to the last good frame first. **Any other fault is corruption**: a bad checksum, length, type or order with a frame behind it, a turn that is not the next one, a checkpoint of a turn that the file does not hold, a head that is wrong in a field: the record is refused. (A length field that is corrupted into one that reaches past the end is read as a torn tail: the reader then stops early, it never hands out altered turns; the fuzz tests pin this.)

* **Bounds.** A record is at most 48 MiB (three times the turn log's limit); all the records of the running rooms together at most 256 MiB (`--restart-budget-mb`: the budget counts the files that rooms hold open, not a stale file whose delete failed, a record that waits on disk or the folder of refused records, which has a bound of its own of the same size); a write that fails (a full disk, a quota, `EFBIG`: S3.89 makes a real one), a record that passes its size, a budget that is used up, and a turn log that passed its limit (the room could no longer give the match to a player who comes back, so a restart could not hold its seats) each **end the record at once**: the file is **deleted** (a record that stops in the middle of a match would bring it back at the wrong tick), the room plays on and its status says why (`record.note`), the log gets a line, and the budget has its bytes back. A match is never harmed by its record. **A delete that fails** (a volume that refuses it) leaves the file of a room that is over, and a restart would bring that room back from it: the store remembers the file as **stale**, the log says so, the status of the room says `record.kept: true` and `record.stale: true` with a note (never `kept: false` while the file is there), and the server tries again **every 10 s** and once more when it is told to stop (S3.109); a line says when the file is gone at last.

### Restoring

At start (`RoomManager::restore_rooms`, called by `main` after the listeners are open) the server reads the `room-*.restart` files of its folder, **newest first** (by the time of their last write: the match that was played a moment ago before one that had been waiting), and **judges** each one (steps 1 and 2; nothing is replayed). What can go on is **queued** (step 3) and replayed **in slices** from the server's loop, which is already running: the server serves while it restores. For each record:

1. **Read and checked all through** (`read_restart_record`; the whole file is read, at most 48 MiB; it is opened once, without following a link and without waiting on a pipe, and the open file is what is checked and read, so nothing can be swapped in between): the magic, every frame's length and checksum, the order of the frames, the turns' numbering, the checkpoints, every field of the head, the commands (the issuer of every one is a seat). A file that fails is **refused**: a line in the log with its name and the reason, the file deleted, nothing else (it is no room: it has no specification that can be trusted). A folder named like a record is not looked at.

2. **Judged.** The record is of this build's rules or it is not: the `protocol` must equal the server's (the game version and the build id may differ: they move with every release, and a deploy that changes no rule must carry the matches over; the log names who wrote the record; the replay below is the defence if a rule changed within a version). The room must be one that this server would make (the same ranges as `POST /rooms`), the record's last write must be less than an hour old (`RestartConfig::max_age_ms`: its players have given up), the server must have room for it, the map must be on this server and **its file must be the one that the match was played on** (the hash in the head), load, and be playable by the roster.

3. **Queued, then replayed in slices.** A record that passed is queued: its code is taken (`POST /rooms` for it answers 409; `GET /rooms/<code>` does not know it until its replay ends). `RoomManager::update` spends at most **5 ms of every pass** of the server on the queue (`RestartConfig::restore_slice_ms`): a room for which a Hello waits first (below), then the newest record. A room's first piece of work reads its record again (the bytes of queued records are not kept) and makes the room: the engine as a client makes it (`init(level, seed, roster)`, the fog, the names), the bots, the keys (`Room::begin_replay`). Then every sealed turn goes into the turn log (what a returning player is given) and into the referee's runner, twenty at a time (`Room::replay_step`; the turns are read one decoded turn at a time by a `RestartTurnReader`), and **at every checkpoint the state hash must be the one that the old server stored for that turn**: a replay that is not the match that was played (a rule that changed within a version, a record that was altered) stops there. The clock is looked at every 20 turns, so a slice ends within 20 turns' work of its time. One room's replay may take **20 s of its own work** (`RestartConfig::replay_budget_ms`: the sum of its slices, not the time that other rooms took between them): beyond it the record is refused as too slow. So is a record that cannot be read again when its turn comes (the file changed while it waited), one whose map changed meanwhile, and one that the turn log cannot hold (its limit, or the server's memory budget). **The crash-loop guard** (`RestartStore::mark_replaying`, the review's L10): before every piece of a record's replay the empty file `<record>.replaying` is made next to it, and it is removed when the piece returns. A start that finds one next to a record (the last run stopped in the middle of that replay: the engine crashed on the match's turns, which were written before they were played, or the process was killed) moves that record to `restart/refused/` unread, with a line in the log and an item in the report, and does not replay it again, so that one record cannot keep a server from ever coming up; the marker of a record that is not there is removed when the folder is prepared. A stop by `SIGTERM` never leaves one (it is looked at between the pieces; S3.124).

4. **Brought back** (`Room::begin_restored`, when **its own** replay ends, **with a clock that starts then**: the time that the replays of the other rooms take is no part of any room's pause, so the 90 s wait of step 5 and the pause cap are not eaten by them; the Hellos that waited for it go through the door at once). The room has its **code** (a Hello with a key finds it as before the restart), the state `running`, the turn count and tick of the record, `restored: {turns, replay_ms, state_hash}` in its status. Every seat of a person is **ABSENT** (`Attendance::seat_restored`): the match is **paused** for everybody until the players come back with their keys (protocol 10: Hello, Welcome, CatchUp or Start + Loaded + Begin + CatchUp, the stream, `CaughtUp`, the referee's comparison at the restored tick, Presence); a seat that the match had **dropped** before the restart (the engine knows: its Drop is in the turns) stays Dropped and its key is told so; a seat without a key is dropped at once. **The bots sit down again** at the restored tick (their tasks are soft, `docs/BOTS.md`: a bot that was running goes on from what it sees; a restored Medium bot has its decisions counted from 0 and looks every 20 ticks again). The record is opened again for appending (a torn tail is cut off): the room goes on writing the same file. **`GET /busy`** (the public answer that a deploy waits on) counts the room as a match that runs, and its held seats as people, for **5 minutes after the restore** (`kRestoredBusyWindowMs`: the players need that long to notice, wait for the server and come back, and a restart now would interrupt them again). After that a room that nobody has come back to counts nothing (it would hold a deploy for the pause cap, 30 minutes to 24 hours), and a player who is back counts as itself (S3.102).

5. **What waits, and for how long.** An absence that a restart causes is **excused**: nobody lost a link. The vote about such a seat opens **after 90 s** (`--restart-vote-seconds`, 30 - 3600; never less than the room's own `hold_vote_seconds`), not a lost link's 30 s: every player has to notice the loss (a closed link at once, 10 s of silence otherwise), wait for the server (a deploy is a build and a start: tens of seconds), reconnect (the clients try every 2 s) and catch up, and a browser tab in the background wakes late; the first player who is back must not be able to vote out the neighbour who is a few seconds behind. The excused absence **adds nothing to the seat's away time** when the seat is back and is **no loss for the flapping rule** (a later loss of the same link is judged as the seat's first: N2.96). Everything else is as for any absent seat: the key holder's budgets (twelve Hellos a minute, ...) start fresh; **the restart's pause counts toward the match's total pause**, so at the cap (30 minutes by default) every seat that is not back is dropped and **a room whose players never come back ends "everybody left"** by the existing rule (S3.92); the wall-clock limit `run_ms` counts the play before the restart (the 5 s of the dialog and 50 ms a turn) and leaves the pause out (S3.98); the clocks are the new server's own (its uptime starts again: the tests start it at 0.5 s, a second before the wrap of its 32-bit clock, and half way: S3.92).

6. **Not restored: a failed room, with the reason** (decided at once when the record is judged, or when its replay is refused). A record that was read and cannot be brought back (another network protocol, a map that is gone or changed, older than an hour, a replay that does not agree with a stored hash, a room that this server would not make, a replay that would take too long, a turn log that cannot hold the match, no room) becomes a **failed room** with the reason in `reason` (`"ended by a restart of the server: the match was started by v0.1.9 (protocol 11), this server is v0.2.0 (protocol 12), and a match cannot go on across a change of the rules"`): the control interface shows it (state `failed`, the players' names, the ticks), the log and the result file report its end once, a Hello for its code is `NoSuchRoom`, its code is taken until its keep time is over, and its record is **moved to `restart/refused/` and kept for 24 hours** (`RestartConfig::refused_keep_ms`: the folder is purged of older files when the server starts and is held under the same budget as the records, the oldest first; a record that alone passes it is deleted; a record that cannot be read at all is deleted at once): an operator whose map was missing for a moment, or whose server was a version behind, moves the file back (S3.110). **A protocol or rules change therefore ends the old matches, with a clear reason**; a deploy that wants to keep them must not change either number, and should wait for a server with no running match (the deploy job of the CI is meant to do that; it is not part of this section).

7. **A match that had ended** when the server stopped (the record holds the turn that ended it, the room had not finished yet) is **finished at once**, with the referee's final hash (the same as the match that was never interrupted: S3.94), its result rows and the report of its end.

**A Hello for a room that is still queued is parked** (`parked_count()`): the connection and the decoded Hello wait in the manager, with no hello timeout, until the room is restored or refused, and then go through the door as any other Hello: a key that fits a seat gets the rejoin `Welcome` and the catch-up, a stranger or a wrong key `MatchRunning`, a refused room `NoSuchRoom`, and a Hello that brings a create block for a public code whose room was refused makes a new room, as ever (S3.116, S3.119). Bounds: `max_pending` (128) Hellos wait in all, the next link is dropped without an answer (a `Reject` is final for a client, a dropped link is tried again), and a room takes as many as its `max_connections`, the next link is dropped without an answer too (it was told `Full`, which is final for a client: silent Hellos of anybody who knows the code could take these places and end a player's way back; the review's L1); a parked connection that closes or sends more than 8 messages after its Hello is dropped, and so is one that has waited `ServerLimits::park_timeout_ms` (a minute: a client takes 10 s without a Welcome for a failure and says Hello again); what a parked peer sends after its Hello reaches the room (S3.118). **`GET /busy`** counts every queued record as a match and its persons as people (a bot is none), so a deploy waits for the restore and a second restart in the middle of one is not let in (S3.120). The control interface does not list a queued record: it is no room yet. The stop flag (`SIGTERM`, `SIGINT`) is looked at between the records that are judged and in every pass of the loop: **every record that is not back (queued or half replayed) stays on disk as it was**, nothing opened again, cut, written or deleted, and the log says how many (S3.106, S3.121; with the real program S3.107).

### Stopping: SIGTERM and SIGKILL

`SIGTERM` and `SIGINT` stop the server within a moment: every room that keeps a record makes it durable (`fsync`; a record that the disk refuses is dropped), **the records stay where they are** (a record is deleted when its room is over, never because the server stops), the rooms that keep none are closed as before; the log says `stopped: N restart record(s) made durable and kept (T ms)` and the exit status is 0. The real program exits **2 ms** after the signal in the test (S3.95); `docker-compose.stack.yml` and `docker-compose.server.yml` set **`stop_grace_period: 15s`** (docker's default is 10 s): the flush is one fsync per running room, a few milliseconds each, so 256 rooms (the most) at a slow volume's 30 ms are 7.7 s; the 15 s are twice that and a margin. **`SIGKILL`** (what docker sends after the grace, a crash, the OOM killer) leaves the records as the turns wrote them: no turn is lost that a player has seen, only the last second of fsync's durability (ten on a slow disk) against the machine's own death (above).

### The limits

| what | number |
|---|---|
| a record | at most 48 MiB (`RestartConfig::max_record_bytes`) and 1,800,000 turns (`kRestartMaxTurns`, 25 hours of play; judged from a frame's header, a record with more is refused as corrupt), a frame at most 1 MiB, a head at most 8 KiB |
| all the records of the running rooms | 256 MiB (`--restart-budget-mb`, 1 - 4096); files that are not open (stale, queued, refused) are not counted |
| the file's durability | `write()` for every turn (survives the process), `fsync` once a second per room and at SIGTERM (survives the machine up to the last second; ten on a slow disk) |
| a record's age | restored when its last write is less than an hour old |
| the replay | at most 20 s of a room's own work in all (`replay_budget_ms`, the sum of its slices); 5 ms of every pass of the server for the whole queue (`restore_slice_ms`); the turn log's own limits and the server's memory budget apply |
| a Hello that waits for its room | at most a minute (`park_timeout_ms`); 128 in all (`max_pending`: the next link is dropped), a room's `max_connections` (32) for one room (the next is told `Full`); 8 messages after the Hello |
| the vote after a restart | 90 s (`--restart-vote-seconds`), never less than the room's `hold_vote_seconds` |
| the cap after a restart | the room's `max_pause_seconds` (30 minutes by default), the restart's pause counts |
| rooms | the server's `--max-rooms`; one record and one open file a room (a room that keeps a record holds its file open for the whole match); a waiting room has none |
| keys | the record's: the same 16 bytes per seat as in the Welcome |

### Options and the stack

`--restart-dir DIR` (default: the folder `restart` of `--results-dir`; without a results folder the server keeps none and says so; an explicit folder that cannot be used (it is not a folder, it is locked by another server, or a probe file cannot be written in it: a read-only volume, a quota, a full disk) stops the server with status 1, the default one is given up with a line in the log), `--no-restart-records` (the two exclude each other: status 2), `--restart-vote-seconds N`, `--restart-budget-mb N`. Only rooms that hold seats keep a record (every room does unless `--no-reconnect` or the room's `"reconnect": false`). **One server to a folder**: the store locks the folder for its life (the file `.lock`, `flock`; Windows: opened with no sharing), because two servers on one folder would write each other's records. A second server cannot take it: with an explicit `--restart-dir` it stops with status 1, with the default folder it logs that restart records are off and runs without them. The lock goes with the process, however it ends; the temporary files of a record that was being made are removed only by the server that holds the lock (S3.104, S3.105). The status JSON of a room has `"record": {"kept", "stale", "bytes", "note"}` and `"restored": {"turns", "replay_ms", "state_hash"} | null`.

### Limits (documented, not fixed)

* **A waiting room is not kept** (it has no match to bring back): a restart empties it, its players join again (a public room is made again by the first Hello that brings a create block; a room of the control interface is gone and its operator makes it again).

* **The machine's death** can take the last second of turns, ten seconds on a slow disk (see "Writing"); the players ahead of the record start the match from nothing again.

* **A vote that was won and whose Drop was not sealed yet is undone by a restart**: the votes are not in the record and the seat's Drop is a turn, which is in the record only once it was sealed; the vote starts again after the restart (and the seat is still held).

* **A pause longer than an hour does not survive a restart**: a record's age counts from its last write, and a pause writes nothing (no turn is sealed), so a room that waited for a player for more than an hour (`--max-pause-seconds` allows 24 hours) is refused as given up at the next restart, though its pause has not reached its cap.

* **The attendance's own bookkeeping is not in the record**: how long each seat was away and how much pause the match had spent before the restart start again at 0 (a match that had paused for 20 of its 30 minutes has 30 again); the cap still bounds the wait for any one restart.

* **The restore takes the server's time in slices, but not all of it is sliced**: judging the records at the start reads each file whole (about 5 ms a MiB: a record at the limit of 48 MiB takes a quarter of a second, and the first piece of its room reads it again), and until a room is back its players' Hellos wait (a minute at the most, then they say Hello again) and `GET /rooms` does not list it. A restart in the middle of a restore leaves the records as they were and the next start does it all again.

* **Windows** sets no permissions on the folder and the record (they take those of the folder: it must be private), and its flush is `FlushFileBuffers`.

* **A record is as private as its folder**: whoever can read the volume can take the seats of the matches that run (they hold the keys). The folder is mode 700 on POSIX.
