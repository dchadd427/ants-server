- **Repository hygiene:** `tools/check_hygiene.py` (`test_hygiene.py`; `--list` prints every file over its target size) fails the tools tier, so CI, when the repository gets worse: a document or a code file over the safety cap, a document README.md does not reach by links (every `docs/**/*.md`), a link to a heading (`file.md#anchor`) that names no heading or a link to a `.md` file that is not tracked, a private planning name or a commit trailer in a public file, more `ASSERT_TRUE` definitions than the constant (2), a `.cpp` that no `CMakeLists.txt` names. All size numbers are in `tools/size_limits.py`: a document aims at 75 KB; at 90 KB the check warns, from 75 KB it says so more softly (CI's python test runner prints the check's `::warning` lines of a passing run, so GitHub shows them on the pull request: at most ten, the files closest to their limit first, and the long lines as one notice): split it by topic as a pure move (`tools/check_doc_move.py` proves it: every section in its own words and order, blank lines and links included); 125 KB fails. Never trim or join text to fit. Code files: production 1,500 lines, tests 2,500, a warning from 90% of that and a failure at 125%. The few files that are over the cap today wait in `SPLIT_PENDING` (names only: they warn, and a name is removed by the split).
